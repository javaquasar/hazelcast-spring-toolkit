# Release Notes: v0.12.0

## Topology Switching

- Added shared `hazelcast.toolkit.cluster-name`,
  `hazelcast.toolkit.network.seed-members`, and
  `hazelcast.toolkit.enterprise-license-key` settings for client and member
  modes.
- Kept the existing client/member-specific connection settings as fallbacks, so
  current applications remain compatible when the shared settings are absent.
- Updated the member-to-client migration scenario for all three Spring Boot
  starters to reuse the shared connection settings and change only
  `hazelcast.toolkit.instance.mode` between application runs.

## Cache Topology Fixes

- JCache manager creation now selects `HazelcastClientCachingProvider` for a
  live Hazelcast client and `HazelcastServerCachingProvider` for a live member.
  This fixes the client cast failure that previously prevented member-mode
  applications from starting with JCache auto-configuration enabled.
- Native Hibernate L2 configuration now follows the live Hazelcast endpoint,
  including externally supplied instances used with `instance.mode=NONE`.
- Added the topology-neutral
  `hibernate.cache.hazelcast.instance.name` application alias. The toolkit
  translates it to the provider-specific underscore key required by the active
  topology.
- Corrected member-mode Hibernate binding to use
  `hibernate.cache.hazelcast.instance_name` and
  `hibernate.cache.hazelcast.use_native_client=false`.
- Client near-cache metrics are no longer registered in member mode. Hibernate
  L2 metrics remain independent.

## Migration

- Prefer the shared toolkit connection settings in applications that switch
  between client and member modes.
- Remove explicit `hibernate.cache.hazelcast.use_native_client`,
  `hibernate.cache.hazelcast.instance_name`, and
  `hibernate.cache.hazelcast.native_client_instance_name` values from
  switchable application profiles.
- Usually no Hibernate instance-name property is required. When an explicit
  value is needed, use
  `spring.jpa.properties.hibernate.cache.hazelcast.instance.name` in both
  topologies and keep it equal to the live Hazelcast instance name.
- Explicit provider-specific values remain supported when they agree with the
  live topology. Contradictory values now fail fast during startup.

## Compatibility

- Java remains `17`.
- The Hazelcast baseline remains `5.7.0`.
- Spring Boot `2.7.18`, `3.5.7`, and `4.0.0` remain the supported build lines.
- The default instance mode remains `CLIENT` and the default Spring Cache mode
  remains `JCACHE`.
