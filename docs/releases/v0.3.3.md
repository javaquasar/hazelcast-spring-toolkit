# hazelcast-toolkit v0.3.3

`hazelcast-toolkit` v0.3.3 is a diagnostic hardening patch for the `0.3.x`
maintenance line.

## Why 0.3.3

`0.3.2` improved release confidence, metadata, and the Actuator near-cache probe
error path. `0.3.3` continues that work by making diagnostic endpoints more
tolerant of mixed cache providers and by adding guard tests around metrics and
metadata behavior.

## Highlights

- make `/hz-toolkit/hz/jcache/near-stats/{cacheName}` return a structured
  response when a JCache cache cannot be unwrapped to Hazelcast `ICache`
- keep the diagnostic response HTTP-friendly instead of propagating unwrap
  failures as server errors
- preserve `status`, `name`, `cacheName`, `local`, and `near` sections for
  JCache diagnostic failures
- add unit coverage for cache-not-found, unwrap-failed, and local-stats-missing
  diagnostic cases
- assert that near-cache `MeterBinder` instances are idempotent for the same
  `MeterRegistry`
- add map near-stats response contract coverage
- add a metadata guard test for key `hazelcast.toolkit.*` configuration
  properties

## Diagnostic Response Shape

If a cache exists but is not a Hazelcast `ICache`, the diagnostic endpoint now
returns a structured response:

```json
{
  "status": "ERROR",
  "name": "plain-cache",
  "cacheName": "plain-cache",
  "error": "Cache cannot be unwrapped to Hazelcast ICache: plain-cache",
  "local": {
    "available": false,
    "reason": "not a Hazelcast cache"
  },
  "near": {
    "enabled": false,
    "reason": "Hazelcast ICache is not available"
  }
}
```
