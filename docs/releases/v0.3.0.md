# hazelcast-toolkit v0.3.0

`hazelcast-toolkit` v0.3.0 adds configurable Spring Cache mode support for
Spring Boot 2, Spring Boot 3, and Spring Boot 4 while preserving the existing
JCache-backed default behavior.

## Highlights

- add `hazelcast.toolkit.spring-cache.mode`
- keep `jcache` as the backward-compatible default
- add `native` Spring Cache mode using `com.hazelcast.spring.cache.HazelcastCacheManager`
- add `none` mode for applications that provide their own Spring `CacheManager`
- keep `javax.cache.CacheManager` creation separate from Spring `CacheManager` selection
- keep `com.hazelcast:hazelcast-spring` optional and out of starter runtime metadata
- document Spring Cache mode vs Hibernate L2 region-factory mode

## New Spring Cache Modes

The new property is:

```properties
hazelcast.toolkit.spring-cache.mode=jcache
```

Supported values:

| Mode | Behavior |
|---|---|
| `jcache` | Creates a Hazelcast-backed `javax.cache.CacheManager` and exposes Spring `JCacheCacheManager`. This is the default. |
| `native` | Creates Spring's native Hazelcast `HazelcastCacheManager` around the toolkit-managed `HazelcastInstance`. |
| `none` | Does not auto-configure a Spring `org.springframework.cache.CacheManager`. |

## Why Native Mode Exists

Some legacy applications previously used Hazelcast's native Spring cache manager:

```text
HazelcastInstance -> com.hazelcast.spring.cache.HazelcastCacheManager
```

That manager resolves cache names lazily as Hazelcast maps. This means
application code can call `getCache("some.dynamic.cache")` without pre-creating
a JCache cache with that name.

The default `jcache` mode remains the best conservative default for new
applications and Hibernate/JPA-oriented setups, but it is not behaviorally
equivalent for applications that rely on dynamic Spring cache names.

## Dependency Model

`native` mode requires:

```text
com.hazelcast:hazelcast-spring
```

The dependency is intentionally `compileOnly` in the starter modules. It is not
published transitively for users of the default `jcache` mode. Applications that
set `hazelcast.toolkit.spring-cache.mode=native` must add `hazelcast-spring`
explicitly.

If native mode is requested without `hazelcast-spring`, startup fails fast with
a clear message explaining the missing dependency.

## Hibernate L2 Compatibility

Spring Cache mode and Hibernate L2 region-factory mode are separate settings.
This is valid:

```properties
hazelcast.toolkit.spring-cache.mode=native
hazelcast.toolkit.hibernate.l2.region-factory=JCACHE
```

In that setup, application-level Spring caching uses Hazelcast's native Spring
cache manager, while Hibernate L2 continues to use JCache.

## Tests Added

Boot 2, Boot 3, and Boot 4 now have dedicated Spring Cache mode tests covering:

- default `jcache` mode
- explicit `jcache` mode
- explicit `native` mode
- uppercase relaxed binding for `NATIVE`
- `native` wrapping the existing toolkit-managed `HazelcastInstance`
- `native` not creating an additional embedded Hazelcast member
- `native` keeping `javax.cache.CacheManager` available
- lazy dynamic cache-name resolution with real Hazelcast `put/get`
- `none` mode
- user-defined Spring `CacheManager` precedence
- fail-fast behavior when `hazelcast-spring` is missing
