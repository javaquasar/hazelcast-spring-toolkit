# hazelcast-toolkit v0.3.2

`hazelcast-toolkit` v0.3.2 is a small follow-up patch release for hardening the
Actuator near-cache probe after `0.3.1`.

## Why 0.3.2

`0.3.1` already fixed typed id conversion for simple JPA ids. This release keeps
that behavior and adds clearer handling and faster unit coverage around the same
code path.

## Highlights

- return a clear `ERROR` response when `/actuator/hazelcastNearCache` is used
  with composite-id entities
- keep composite ids explicitly unsupported by the probe instead of allowing an
  unclear metamodel failure
- split id-type resolution errors from id-conversion errors in `NearCacheProbe`
- add lightweight unit coverage for `NearCacheProbe.resolveId(...)`
- verify explicit conversion for `Integer`, `Long`, `Short`, `Byte`, `String`,
  primitive equivalents, and value-object ids with static `valueOf(String)`
- preserve legacy fallback conversion when no id type is known
- add lightweight Boot 2 auto-configuration condition coverage for actuator,
  diagnostics, and metrics binders
- standardize near-cache diagnostic responses with `status`, `name`, `local`,
  and `near` sections while preserving existing cache-specific fields
- add Spring Boot configuration metadata for key `hazelcast.toolkit.*`
  properties
- add a GitHub Actions `published-consumer-smoke` suite for testing a published
  toolkit artifact from the example application
- document near-cache actuator troubleshooting and diagnostic response shape

## Actuator Near-Cache Probe

The endpoint remains:

```text
GET /actuator/hazelcastNearCache
```

The probe is intended for entities with a single simple id attribute. If a
composite-id entity is passed, the response now reports a clear unsupported
case instead of continuing into a less helpful failure.

./gradlew build -PreleaseVersion=0.3.2
