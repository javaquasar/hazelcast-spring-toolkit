# Release Notes: v0.10.0

## Highlights

- Added explicit Hazelcast instance modes:
  - `hazelcast.toolkit.instance.mode=client` (default)
  - `hazelcast.toolkit.instance.mode=member`
  - `hazelcast.toolkit.instance.mode=none`
- Added embedded member-mode support through `HazelcastMemberFactory`.
- Added `HazelcastMemberConfigCustomizer` for type-safe member `Config`
  customization.
- Added minimal member properties under `hazelcast.toolkit.member.*` for
  cluster name, instance name, port, public address, and discovery settings.
- Added member-mode safe defaults:
  - `hazelcast.logging.type=slf4j` when not already configured
  - `SpringManagedContext` integration when `hazelcast-spring` is available
- Changed shared auto-configured beans to back off cleanly when
  `instance.mode=none` is used and the application does not provide a
  `HazelcastInstance`.

## Compatibility

The default remains client mode, so existing applications using
`hazelcast.client.*` continue to behave as before.

Member mode is opt-in and should be treated as an advanced deployment topology:
each Spring Boot application instance becomes a Hazelcast cluster member.

## Example

```yaml
hazelcast:
  toolkit:
    instance:
      mode: member
    member:
      instance-name: my-service-member
      cluster-name: dev
      network:
        port: 5701
        port-auto-increment: true
        join:
          auto-detection-enabled: false
          multicast-enabled: false
          tcp-ip-members:
            - 127.0.0.1:5701
```

## Verification

- Added runtime tests for member config creation.
- Added Boot 2, Boot 3, and Boot 4 auto-configuration tests for default client
  mode, explicit member mode, and `none` mode.
- Added Spring configuration metadata coverage for the new instance/member
  properties.
