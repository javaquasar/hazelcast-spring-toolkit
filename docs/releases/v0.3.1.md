# hazelcast-toolkit v0.3.1

`hazelcast-toolkit` v0.3.1 is a patch release for Spring Boot service
compatibility and observability diagnostics.

The main fix is for the standard Actuator near-cache probe:
`GET /actuator/hazelcastNearCache`. The endpoint now resolves the JPA entity id
type from the metamodel before converting the query parameter, so entities with
`Integer` primary keys work the same way as existing `Long` id entities.

## Why 0.3.1

This release does not add a new public module or change the starter dependency
model. It fixes runtime behavior in existing features introduced before
`0.3.1`, so the appropriate version is a patch bump from `0.3.1` to `0.3.1`.

Services that use `hazelcast-toolkit-spring-boot2` can upgrade to `0.3.1` and
remove local debug/test endpoint workarounds for the Hazelcast near-cache probe.

## Highlights

- fix typed id conversion for `/actuator/hazelcastNearCache`
- resolve entity id type through the JPA metamodel in Boot 2, Boot 3, and Boot 4
- support `Integer`, `Long`, `String`, `Short`, `Byte`, primitive equivalents,
  and value-object ids with static `valueOf(String)`
- keep the existing Actuator response shape and add `idType` / `resolvedId`
  fields for verification
- prevent `/hz-toolkit/hz/jcache/near-stats/{cacheName}` from returning HTTP 500
  when Near Cache is not enabled
- return `near.enabled=false` with a short reason while preserving local JCache
  statistics when available
- fix Micrometer binder auto-configuration by returning `MeterBinder` beans and
  letting Spring Boot bind them to the `MeterRegistry`
- keep `hazelcast.toolkit.metrics.enabled=true` and
  `hazelcast.toolkit.metrics.diagnostic-endpoint.enabled=true` as separate
  controls

## Actuator Near-Cache Probe

The endpoint remains:

```text
GET /actuator/hazelcastNearCache
GET /actuator/hazelcastNearCache?entity=com.mycompany.entity.Product&id=99
```

For an entity with an `Integer` id, the endpoint now converts `id=1` to
`java.lang.Integer` instead of trying `Long` first.

The successful response includes the existing fields plus typed id details:

```json
{
  "status": "OK",
  "entity": "com.mycompany.entity.Product",
  "id": "1",
  "idType": "java.lang.Integer",
  "resolvedId": 1
}
```

## Diagnostic JCache Near-Stats

The diagnostic endpoint remains controlled by:

```properties
hazelcast.toolkit.metrics.diagnostic-endpoint.enabled=true
```

When Near Cache is not enabled for a JCache cache, this endpoint now returns a
normal response:

```text
GET /hz-toolkit/hz/jcache/near-stats/{cacheName}
```

The `near` section reports `enabled=false` instead of propagating Hazelcast's
`UnsupportedOperationException`.

## Metrics Auto-Configuration

Micrometer publishing remains controlled by:

```properties
hazelcast.toolkit.metrics.enabled=true
```

The auto-configuration no longer injects `MeterRegistry` into `MeterBinder`
factory methods and no longer manually calls `bindTo(...)` during bean creation.
Spring Boot is responsible for binding the returned `MeterBinder` beans to the
available registry.

This avoids circular dependency scenarios involving `SimpleMeterRegistry` and
the toolkit metrics binders.

```bash
./gradlew :toolkit-spring-boot3:test --tests io.github.javaquasar.hazelcast.toolkit.boot3.Boot3ActuatorNearCacheIntegrationTest --tests io.github.javaquasar.hazelcast.toolkit.boot3.Boot3MetricsIntegrationTest

```

Notes:

- Boot 2 targeted tests passed.
- Boot 4 targeted tests passed.
- Boot 3 targeted test task passed, but Testcontainers-based tests may be
  skipped when Docker is unavailable. Run the same Boot 3 command with Docker
  available before publishing.

For a full release confidence pass:

```bash
./gradlew build -PreleaseVersion=0.3.1
```

For a signed release bundle build:

```bash
./gradlew clean centralBundleAll -PreleaseVersion=0.3.1
```

## Services Upgrade Note

After `0.3.1` is published, Spring Boot 2 services can depend on:

```gradle
implementation "io.github.javaquasar:hazelcast-toolkit-spring-boot2:0.3.1"
```

Then local workaround classes that shadow `hazelcastNearCache` can be removed,
leaving only normal configuration such as:

```properties
management.endpoints.web.exposure.include=health,metrics,beans,info,hazelcastNearCache
hazelcast.toolkit.actuator.near-cache-check.enabled=true
hazelcast.toolkit.actuator.near-cache-check.entity-class=com.mycompany.entity.Product
hazelcast.toolkit.actuator.near-cache-check.entity-id=1
hazelcast.toolkit.metrics.diagnostic-endpoint.enabled=true
```
