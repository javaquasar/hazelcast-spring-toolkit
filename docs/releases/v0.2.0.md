# hazelcast-toolkit v0.2.0

`hazelcast-toolkit` v0.2.0 is the first release line that presents the project as a
multi-generation Spring Boot Hazelcast library with a shared runtime layer,
production-oriented observability, and a unified Maven Central publication model.

## Highlights

- publish the full shared module set under stable `hazelcast-toolkit-*` artifact IDs
- publish `toolkit-spring-boot4` as a regular starter alongside Boot 2 and Boot 3
- introduce shared runtime and spring-common layers for cross-generation reuse
- support explicit `CompactSerializer` registration through `@HzCompact`
- add Hazelcast client naming based on `hazelcast.toolkit.client.base-name` and `spring.application.name`
- expand Hibernate L2, near-cache, metrics, and map-listener test coverage across starters
- document the Hibernate 5 composite-cache-key limitation and the recommended workaround

## User-Facing Changes

### Spring Boot Starters

- Boot 2, Boot 3, and Boot 4 now share the same runtime building blocks for client
  creation, compact registration, listener auto-registration, and metrics wiring.
- Boot 4 is now part of the regular build, regular test suite, and public release set.
- Starter smoke tests and integration coverage are aligned more closely across Boot 2,
  Boot 3, and Boot 4.
- The published starters remain intentionally thin: they provide the toolkit wiring
  without hiding every optional integration behind one oversized dependency.

### Client Naming

A new naming policy derives the final Hazelcast client name from:

- `hazelcast.toolkit.client.base-name`
- `spring.application.name`
- fallback rules when one or both are missing

Examples:

- `hz.client` + `billing-api` -> `hz-client-billing-api`
- `hz.client` + `Billing/API @ EU` -> `hz-client-billing-api-eu`
- no base name + `my-service` -> `my-service`

### Compact Serialization

`@HzCompact` now supports both:

- zero-config reflective Compact registration
- explicit `CompactSerializer` registration per type

The runtime validates that an explicit serializer matches the annotated compact class.

### Hibernate L2 And Observability

- Hibernate L2 configuration has stronger integration coverage for Boot 2, Boot 3, and Boot 4.
- Near-cache, Micrometer, and diagnostic endpoint behavior are covered by dedicated tests.
- The known Hibernate 5 composite-key plus converter limitation is now documented in detail.

### Packaging And Consumer Integration Model

- The toolkit keeps the Spring Boot starters as the primary low-level integration path.
- Applications with strict dependency management or shared-module layouts can still add
  companion libraries explicitly, rather than relying on a single "everything starter".
- Optional integrations such as `com.hazelcast:hazelcast-hibernate` and
  `javax.cache:cache-api` remain explicit add-ons, which keeps Hibernate L2 and JCache
  choices visible in consumer builds.

## Notes For Existing Users

- Maven artifact coordinates now consistently use the `hazelcast-toolkit-*` prefix.
- Boot 4 consumers no longer need an opt-in project switch to build or test the starter.
- The public README and release publishing guide have been updated to match the current module set.
- Consumer verification should continue to run against the published artifacts, not only
  against monorepo project dependencies.

## Recommended Upgrade / Verification Commands

```bash
./gradlew build
./gradlew :toolkit-spring-boot2:test
./gradlew :toolkit-spring-boot3:test
./gradlew :toolkit-spring-boot4:test
```

For a signed release bundle build:

```bash
./gradlew clean centralBundleAll -PreleaseVersion=0.2.0
```

This release is focused on turning the toolkit into a clearer library product:

- stronger starter test parity
- clearer publication flow for Maven Central
- clearer documentation of supported and unsupported Hibernate cache patterns
